# AI Usage Disclosure

**Tool/model:** Claude (Anthropic) and Gemini (Google), used through their respective chat interfaces.

**Purpose:** 
* **Claude:** Utilized to scaffold the initial boilerplate for validation scripts (`validate.py`, `failure_test.py`), bash automation (`backup.sh`, `restore.sh`), and the CI workflow structure.
* **Gemini:** Acted as a technical sounding board for debugging Windows/WSL host port conflicts (phantom locks) and discussing security best practices for Docker environments.

**Files affected:** 
`validate.py`, `failure_test.py`, `backup.sh`, `restore.sh`, `.github/workflows/ci.yml`, `Dockerfile`, `docker-compose.yml`.

**What I changed or rejected:** 
I actively reviewed and significantly modified the AI-generated outputs to align with the project's strict security and architectural requirements:
* **Dynamic Discovery:** Refactored the Python validation scripts to use dynamic container discovery (`docker ps --filter name=^app-`) instead of the AI's suggestion to hardcode `app-01`/`app-02`. This ensures the script continues working automatically when a third instance is added.
* **Security Intervention:** Rejected the AI's initial approach to include `COPY config/app.env` inside the `Dockerfile`. I identified this as a critical security vulnerability (baking secrets into image layers) and manually removed it, reconfiguring Compose to use the root `.env` securely.
* **Script Debugging:** Fixed a syntax bug generated by the AI in `backup.sh` where `pg_restore` was incorrectly using a hyphen (`-`) for standard input during the integrity check, causing the backup process to fail.
* **CI/CD Supply Chain Security:** Fixed the CI workflow's Trivy step myself after the first run failed: it was pinned to `aquasecurity/trivy-action@0.28.0`, a tag that no longer resolves because of the March 2026 supply-chain compromise of that project. Re-pinned to the `v0.36.0` release commit SHA instead of any mutable tag.

**How I independently verified it:** 
* Used `python3 -m py_compile` on the Python scripts and `bash -n` on the shell scripts to verify syntax.
* Validated architecture using `docker compose config`.
* Executed the scripts against the live local stack: 
  - `validate.py` passed **13/13** checks. 
  - `failure_test.py` passed **5/5** checks.
  - Successfully proved database persistence by creating a record, destroying containers, and restoring via `backup.sh` and `restore.sh`.
* Verified the final pipeline execution in GitHub Actions.
